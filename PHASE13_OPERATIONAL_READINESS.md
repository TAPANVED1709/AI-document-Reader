# Phase 13E operational readiness

The API persists one `ProcessingJob` per report in SQL Server. A hosted worker claims queued or retryable jobs with a conditional status update, records the worker id and heartbeat, and limits concurrent processing through `Processing:MaxConcurrentJobs`. Jobs retry transient AI, network, and file errors with bounded exponential backoff. Invalid PDFs and page-limit failures are terminal. Startup recovery moves stale processing rows to `RETRYING`.

The upload endpoint returns `202 Accepted` with `reportId`, `jobId`, and `QUEUED`. Status is available at `/api/reports/{id}/processing-status`; queue counts are available at `/api/queue/health`; review items are available to lab staff and pathologists at `/api/review-queue`. Lab ingestion requires an organization claim, authorized patient association, and an organization-scoped `Idempotency-Key`. Batch upload isolates invalid files.

Limits are configured through `Processing:MaxConcurrentJobs`, `Processing:MaxDurationSeconds`, `Processing:StaleJobSeconds`, and `MAX_PDF_PAGES`. The AI service is server-to-server and has no browser CORS policy. Ollama is optional and is not required for extraction.

The development backup/restore test backed up SQL Server, restored into `AiDocumentReaderRestoreTest`, verified a synthetic report's stored filename, and verified the shared report file remained present. Phase 13E subsequently executed authenticated Docker verification with synthetic LAB_STAFF and patient identities. Evidence is in `PHASE13E_OPERATIONAL_RESULTS.json` and `PHASE13_PERFORMANCE_RESULTS.json`; the reproducible harness is `scripts/verification/phase13e.py`.

The measured ten-report benchmark used four native, four scanned and two hybrid PDFs: four jobs completed, six reached `REVIEW_REQUIRED`, zero failed, and zero duplicate result groups were found. Average queue wait was 3597.4 ms, average processing duration 1579.2 ms, and maximum processing duration 3361 ms. Server-side queue snapshots measured peak processing 2 and peak queued 10. Scanned/hybrid reports preserved the known values but triggered low name, numeric-value or reference confidence review rules. These are synthetic operational measurements, not a production capacity estimate.

AI recovery was verified after the first failed attempt and before the next due retry: the same job completed on attempt two with three results, no validation issues, one analysis run, and its current safe error cleared. The harness overrides `Processing:RetryBaseSeconds` to 20; the production default remains 1 second with bounded exponential retries and three attempts. Completion clears `NextRetryAt`. Exhausted stale jobs become terminal rather than restarting indefinitely.

`Phase13OperationalTests` exercises two independent concurrent claims against the same relational database, cancellation of a running worker followed by an aged stale timestamp and replacement worker, and six queued jobs with instrumented AI calls. Exactly one duplicate claim succeeds; stale recovery preserves the job ID and finishes on attempt two; measured active calls peak at two and the initial queue peaks at six. Processing capacity is acquired before a claim, and shutdown waits for active tasks before disposing its semaphore.

Authenticated explanation requests now serialize camelCase to match FastAPI. The response model rejects non-string finding fields incompatible with the API response DTO, so malformed model output takes the existing deterministic fallback. Loopback HTTP tests cover unreachable providers, timeouts, invalid JSON/output and missing models. A real authenticated Docker request with an unreachable Ollama returned HTTP 200, `provider=deterministic`, `usedFallback=true`, and left the report unchanged. A focused three-request test measured two concurrent local explanation calls.

Removing Tesseract at the container boundary produced `REVIEW_REQUIRED`, `OCR_UNAVAILABLE`, `ocrRequired=true`, `ocrApplied=false`, and zero results for a scanned PDF. Native processing still completed with three results and both OCR flags false. The binary was restored. The final Docker run inspected metadata on 70 persisted audit records; none contained report content, OCR text, medical result dumps or credentials.
